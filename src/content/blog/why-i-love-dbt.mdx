When working in the **financial sector**, data accuracy isn't just a nice-to-have; it's a regulatory requirement. For years, data teams struggled with stored procedures that lacked version control, testing, and CI/CD.

Enter **dbt (data build tool)**.

## Software Engineering for Data

With dbt, everything is code. It allows us to:

1. **Version Control everything**: Our transformations live in Git.
2. **Test automatically**: We can assert that `transaction_id` is unique and not null.
3. **Lineage**: We get a beautiful DAG of our data models.

```sql
-- Example dbt model
with raw_transactions as (
    select * from {{ source('finance', 'raw_transactions') }}
),
cleaned as (
    select
        transaction_id,
        user_id,
        amount_cents / 100.0 as amount_usd,
        created_at
    from raw_transactions
    where status = 'completed'
)
select * from cleaned
```

For a data engineer at Bekk, helping clients trust their data is the core mission. dbt makes that trust provable.
